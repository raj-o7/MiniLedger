## What was implemented

### Backend (`backend/`)
- Express 5 + TypeScript API with a central error handler and consistent JSON errors.
- Environment configuration validated with Zod at startup (`src/config.ts`).
- PostgreSQL schema with foreign keys, CHECK constraints and an index
  (`migrations/001_initial_schema.sql`) and a small migration runner (`npm run db:migrate`).
- Phone + mock OTP login:
  - 6-digit codes from `crypto.randomInt`, printed to the terminal
  - codes stored only as HMAC-SHA256 hashes
  - 5-minute expiry, 5 attempts max (counted atomically), 30-second resend cooldown,
    only the newest code is valid, codes are single-use
  - JWT (HS256) tokens, `GET /api/auth/me`
- Protected loan endpoints: create, list (with `status` filter), details, mark repaid, summary.
- Every loan query is parameterized and filtered by the logged-in user's id.
- Money stored as integer cents; dates stored as `DATE` and returned as `YYYY-MM-DD`.
- Overdue rule and summary calculations as pure, unit-tested functions (`src/loans/loanRules.ts`).
- "Today" computed in a configurable timezone (`APP_TIMEZONE`).
- Optional receipt image (JPEG/PNG/WebP data URI, ~2 MB max).

### Mobile (`mobile/`)
- Screens: Login, OTP verification, Dashboard, Loan list, Add loan, Loan details.
- Input validation with per-field messages (phone, OTP, name, amount, dates).
- Loading, error (with retry), and empty states on every data screen; pull-to-refresh.
- Overdue highlighting (red border/background/text and an "Overdue" badge).
- Filter chips: All / Pending / Overdue / Repaid.
- Mark-as-repaid with a confirmation dialog.
- Optional receipt photo from the photo library, with preview and remove.
- Token kept in secure storage; automatic logout on 401.
- Backend URL configurable with `EXPO_PUBLIC_API_URL`.

### Files removed from the Expo template (and why)
`create-expo-app` generated these extra items, which were deleted right after scaffolding:
- `mobile/.git/`: the template ran `git init` **and created an "Initial commit"**. You asked for
  no commits and want to manage Git yourself; a nested repository inside `MiniLedger/` would also
  get in the way when you create your own repo.
- `mobile/LICENSE`: the template's MIT license naming "650 Industries, Inc. (aka Expo)" as
  copyright holder. Choosing a license for your project is your decision.
- `mobile/AGENTS.md` and `mobile/.claude/settings.json`: AI-assistant configuration files added
  by the template; not part of the app.

**How a real PostgreSQL was available:** PostgreSQL is not installed on the build machine and

(PostgreSQL **18**) was installed in a temporary folder **outside the project** and run on port
54329. It is not a dependency of MiniLedger. You need your own PostgreSQL (see README).

**What the integration tests cover:** health check, 404 for unknown routes, malformed JSON;
phone validation and normalisation; OTP hashing, cooldown, wrong code, single use, 5-attempt
lockout, expiry, same phone → same account; missing/invalid token; creating loans (amount stored
as cents); every validation rule; future loan date; receipt stored, hidden from the list, returned
in details; list ordering, overdue flags and all four filters; empty list; 400/404 for bad/missing
ids; repayment (default date, chosen date, twice → 409, future/too-early dates → 400); summary
totals including a loan that was overdue and then repaid; **user isolation** (another user cannot
list, view, repay or count your loans); database constraints rejecting bad rows directly.

### Manual end-to-end checks
1. **curl against the compiled server** (`npm start`): health → request OTP (code read from the
   server's terminal output) → verify → create two loans → list (one flagged overdue) → repay →
   summary (`totalLent 3300.75, totalRepaid 2500, outstanding 800.75, overdue 0`) → 401 without a
   token → validation errors listing every bad field. Responses are quoted in API_DOCUMENTATION.md.

## Remaining issues and limitations

1. **Mobile UI not run on a device or simulator.** The build machine has no Xcode (no iOS
   Simulator) and no Android emulator. Screens are covered by typechecking, component/unit tests,
   successful Metro bundles for both platforms, and the live API-client check, but nobody has
   tapped through them yet. **First thing to do:** run the app with Expo Go and walk through
   login → add loan (with photo) → list → details → repay → dashboard.
2. **Receipt picker not exercised on a real device** (needs a photo library). Size/format limits
   are enforced on both sides and covered by tests.
3. **OTP is mocked**: codes are printed to the server log in every environment. Replace
   `logOtpToConsole` with an SMS provider before any real use.
4. **No IP-based rate limiting** on the auth endpoints (only per-phone cooldown and attempt limits).
5. **Receipt images are stored in the database** as base64 text. Fine for a small app; use object
   storage for larger scale.
6. **Not implemented (not requested):** editing or deleting loans, partial repayments, multiple
   currencies (the app displays INR; change `LOCALE`/`CURRENCY` in `mobile/src/utils/format.ts`).
7. **Web target not supported** (`expo start --web`): `expo-secure-store` doesn't work in
   browsers and the API doesn't enable CORS.
8. **"Today" can differ between phone and server** near midnight if the phone's timezone differs
   from `APP_TIMEZONE`. The server's answer is the one that counts; the phone only uses its date
   for instant form feedback.
9. **`npm audit` warning in mobile** (node-forge via Expo CLI): see Dependencies above.
10. **No Git repository was created** for `MiniLedger/`, and no commits were made. The template's
    auto-created repo was removed as described above.
